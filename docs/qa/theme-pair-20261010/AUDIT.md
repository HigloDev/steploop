# 循阶 1.1.2 · App 深浅主题修复与复查

本次修复 App 本身的浅色模式混用深色页面问题。保留已经确认的 1.1.2 布局、橙色品牌和训练流程，补齐所有训练阶段及共用控件的浅色配色。

[打开实际截图图册](index.html)。图册包含 45 组对照、90 张 Android 原生截图，使用隔离测试 App 与合成训练数据。每张图均可打开包含系统栏的原始截图。

## 问题、修改方案与实施

| 发现的问题 | 修改方案 | 实施结果 |
| --- | --- | --- |
| 训练页面固定引用深色 palette，浅色模式仍是黑底 | 在现有 theme.ts 中维护训练的浅色、深色配色，并在渲染时根据系统主题选择 | 标定、标定完成、爬升、下行、等待、步数估算、启动、启动失败、保存中及两种保存失败状态均完成对照 |
| 大数字、刻度、状态栏和长按按钮使用模块级固定样式 | 共用控件使用主题 hook 与按配色生成的样式；长按进度填充也采用语义色 | 运行中切换主题立即更新背景、文字、按钮和进度，已标定层数保留 |
| 训练导航背景和状态栏强制深色、保存失败卡片写死黑底 | 导航背景、四个状态栏分支及失败卡片全部接入当前训练主题 | 页面进入、异常状态与恢复操作的配色保持一致 |
| 浅色橙色按钮和选中控件用白色文字，部分次要文字及危险进度对比度不足 | 调整主按钮前景、次要文字、权限成功图标及长按填充，区分橙色填充和橙色文字 | 正文、训练提示及正常/按住状态的主要文字配色通过 4.5:1 对比度检查 |
| 分享页切换主题后，海报准备状态仍对应旧主题，保存一直失败 | 主题改变时重新挂载导出画布，使图片加载完成信号对应当前主题 | 已先在原实现复现“海报正在准备”，修复后在同一页面切换深色、浅色，均成功保存 1080×1350 PNG |

训练共用组件的动画、长按确认时长、保存/放弃保护与业务数据模型保持原有实现。海报沿用已确认的暖纸色设计，不随编辑页面的背景翻转。
