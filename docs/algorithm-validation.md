# 循阶识别算法验证协议

本协议用于把“真机感觉更准”变成可重复、可比较的工程指标。任何会改变步数、转向、气压、楼层推进或路线学习结果的代码，都应使用同一批诊断包离线回放。

## 数据闭环

1. 在开发构建中进入「设置 → 传感器诊断」。
2. 选择一条已完成首次采集的参考路线。
3. 选择真实动作和手机携带位置。
4. 向上爬楼时，在双脚到达新楼层平台后标记楼层，在身体完成转向时标记转弯。
5. 结束采集并通过系统分享保存 JSON 文件。
6. 把脱敏后的诊断包放到工作区之外的数据目录，不提交包含真实用户运动数据的文件。
7. 使用离线回放命令生成报告：

```powershell
npm run diagnostics:replay -- --out C:\diagnostics\current-report.json C:\diagnostics
```

回放报告为 JSON，包含最终楼层误差、楼层事件准确率、召回率、识别延迟和负样本误报。
将当前报告与已冻结基线比较时使用：

```powershell
npm run diagnostics:replay -- --baseline C:\diagnostics\baseline-report.json C:\diagnostics\*.json
```

发布候选版必须再执行硬门禁：

```powershell
npm run diagnostics:gate -- C:\diagnostics\current-report.json
```

V2 报告附带每个输入文件的 SHA-256 内容哈希、样本质量和数据集指纹；
`invalid` 样本保留在清单中，但不进入准确率与误报率指标。

准确率、误报率或 P95 延迟超过允许退化范围时，命令以失败状态退出，可直接接入 CI。

## 隐私边界

诊断工具仅在开发模式显示，采集期间数据保存在内存中。导出包会自动：

- 删除路线地点、地址和经纬度；
- 将路线名替换为「诊断路线」；
- 删除设备型号；
- 将传感器时间戳转换为相对采集开始的毫秒数；
- 不进行网络上传，仅在用户主动结束后调用系统分享。

路线运动模板、携带方式、操作系统版本和原始运动传感器值会保留，因为它们是复现识别结果的必要条件。

## 第一批数据矩阵

| 维度 | 最低覆盖 |
|---|---:|
| 建筑路线 | 10 条，包含剪刀梯、直跑梯、长短平台 |
| Android 设备 | 5 款，至少 3 个品牌 |
| 测试者 | 5 人，不同步幅与速度 |
| 携带方式 | 裤袋、腰部 |
| 每条路线向上样本 | 10 次 |
| 每类负样本 | 20 次 |

负样本必须覆盖平地行走、静止、电梯上行、电梯下行、下楼和扶梯。气压计可用与不可用设备分别统计，不能混在一个平均数里掩盖退化。

## V2 质量门槛

| 指标 | 发布门槛 |
|---|---:|
| 完整路线最终楼层准确率 | ≥ 98% |
| 楼层事件 Precision | ≥ 96% |
| 楼层事件 Recall | ≥ 96% |
| 楼层识别延迟中位数 | ≤ 2 秒 |
| 楼层识别延迟 P95 | ≤ 4 秒 |
| 负样本误报率 | ≤ 1% |
| 训练完成无崩溃率 | ≥ 99.8% |

如果一个修改提高总体平均值、但让任何设备类别或携带方式退化超过 2 个百分点，不得直接合并。应先找出设备采样率、气压漂移或路线结构差异，再决定采用分组参数还是回退。

## 标注规则

- `floor`：双脚已经到达新楼层的平台，不在半层转弯处标记。
- `turn`：身体方向完成明显改变时标记，不在刚开始旋转时标记。
- 向上爬楼样本的 `completedFloors` 由人工楼层标记计算。
- 所有非向上爬楼动作的真实完成楼层固定为 0，用来检测误报。
- 锁屏、切后台或信号断流自动记录为 `gaps`，不可从报告中静默删除。

## 合并规则

算法提交至少要附带：

1. 使用的数据集版本或文件清单哈希；
2. 修改前与修改后的汇总报告；
3. 分设备、分携带方式和分动作类型结果；
4. CPU、内存和 30 分钟耗电对比；
5. 已知失败样本及失败原因。

在第一批真实数据尚未达到矩阵要求前，合成测试只能作为逻辑回归保护，不能作为“算法已经精准”的证据。
