# 新皮肤建设记录模板

复制本表用于建设记录，并同步登记 `registry.json`。索引先于源码；选择页由运行时目录自动生成。

| 项目 | 填写内容 |
|---|---|
| 稳定ID | 英文短横线格式；发布后不复用、不重命名 |
| 显示名 | 用户在选择页看到的名称 |
| 方向与来源 | 原创配色意图、参考链接；实际色值由本项目验证 |
| 基线 | 开发基准版本及提交；不填成本次功能已发布 |
| 浅色 | 背景、表面、前景、操作、操作文字、周卡及强调色 |
| 暗色 | 同上，单独设计 |
| 语义检查 | 警告、错误、成功与品牌装饰可以区分；文字对比度通过 |
| 素材 | Logo、共享场景、完成徽章、四页页头及必要暗色覆盖；本地路径、来源、SHA-256、透明边缘、原图分辨率、失败回退 |
| 布局 | 360dp的四页内容比例、页头高度、卡片/底栏密度及叠放关系；320dp/130%字号降级 |
| 范围 | 训练／教练／记录／设置四个主入口；教练五类深页、训练、完成、帮助、引导、弹窗、空态、失败态、单次与每周海报 |
| 自动检查 | 目录与运行时一致；主题与偏好测试；类型、回归及Android导出 |
| 原生证据 | 同数据/字号的十二张核心页；入口切换、教练表单、冷启动、系统切换、大字体及分享 |
| 阶段 | planned / implemented / automated-pass / native-verified / released |
| 发布 | 候选包、提交、测试范围、实际公开版本；未发布填“未发布” |

操作顺序：

1. 阅读建设索引和规范，将条目登记为 `planned`。
2. 在 `src/skin-catalog.ts` 增加完整浅暗配色，在`src/skin-assets.ts`登记三种共享素材、四页页头及暗色差异，在`src/theme.ts`登记测量尺寸。不要复制页面、添加皮肤专用路由或修改训练逻辑。
3. 通过 `src/theme.ts` 输出已有语义token；新增语义要说明已有token为何不足。
4. 运行 `npm run typecheck`、`npm run test:theme`、`npm test`、锁定依赖检查和Android导出。
5. 参照 `scripts/fidelity-native-qa.py` 与 `graphics-native-qa.py` 在专用模拟器采集实际页面，保留内容比例对照和源码指纹。更改目录时同步扩充捕获列表、证据检查器和背景期望值，原生包必须为`.uiqa`。
6. 记录检查结果、截图与遗留问题，再更新索引状态。源码、模拟器验证和公开发布分别登记。
